# The Requested Output Must Govern the Workflow

## I -- Idea

A reusable workflow should preserve the requested output and permitted side effects before it imposes its default sequence.

The session supplied several concrete versions of this problem. Suggi wanted permanent knowledge to distinguish general investment understanding from company-specific understanding. A company lesson did not have to become a general essay before it could be saved. We established separate typed structures, retained existing general-topic depth requirements, and subsequently accumulated company knowledge alongside the reusable principles. That was a change in the destination of understanding, not a reason to create empty files for every holding or claim that every research pass produced a new universal insight.

Source presentation then exposed a related mismatch. I produced technically explicit repository references and separated source groups, but the user wanted the lean style already used in the Library. Subsequent instructions removed obsolete update notices, combined the source lists, simplified repository entries and made the entry-writing guidance self-contained. In the unpromoted-learning inbox I interpreted a footnote-like placement as permission to use automatic Markdown footnotes. The stored text remained ASCII while the renderer generated superscripts and return links. The user's complaint concerned the visible result. A byte-level check could answer whether the file was ASCII, but it could not establish whether the displayed reference matched the requested appearance.

The final requested convention used ordinary bracketed numbers without enclosing parentheses. The migration preserved the evidence identities and source lists rather than merely replacing attractive-looking punctuation. The examples changed with the actual content, and the capture procedure was aligned so the next learning pass would not reintroduce the rejected form. These actions were useful because they kept the user's presentation contract and the citation's evidential job separate while satisfying both.

The later ASML request made the same distinction at workflow level. Suggi explicitly wanted research informed by the frameworks, not a scored framework application, a valuation, or a company report published to Investing Hub. The questions about technical protection, supplier dependence, customer adoption and cash quality remained useful. Their usefulness did not authorize running every questionnaire or producing the usual valuation tables. A warranted company knowledge note could record that understanding without pretending to complete the company's investment case. A separate clarification authorized only the normal session-end logbook write in Investing Hub.

My blank-page explanation before the reflection review was that correct mechanics can still produce the wrong artifact. The open questions were whether this was genuinely different from the earlier role-before-length lesson, what had been verified rather than assumed, and whether simplification had weakened provenance. Reading the prior reflections and the actual results narrowed the answer. The old role distinction remains valid. This session adds an executable mode choice before the workflow, and separates source integrity from display behavior and from the destinations the user permits.

## O -- Opinion

Confidence: high (90%), as a subjective judgment about the observed failure mechanism and its correction, not a measured success rate for future research.

I favor an explicit scope choice over treating the fullest available procedure as the safest default. A workflow that automatically expands a request can be incorrect even when every additional step is competently performed. In investment research, a formal score or scenario table also carries an implication about the breadth of work behind it. Producing that familiar shape during a research-only task can suggest completed assessment where the user requested understanding. The appropriate restraint is to retain the analytical questions while declining the unsupported output form, not to abandon financial reasoning or give an ungrounded company story.

The strongest objection is that narrowing a procedure might become an excuse for skipping difficult evidence. That would be a different failure. Research-only scope still requires verified facts, careful dates, clear accounting units and contrary evidence. It does not authorize turning a joint customer announcement into independent proof of commercial returns, or turning a funding balance into cash available to owners. The ASML note consequently distinguishes observed disclosures, management expectations, my interpretation and questions left open. The absence of scores is a boundary on claims, not a reduction in the obligation to support the claims actually made.

I also favor treating presentation requirements as functional requirements when they govern how the user reads and maintains knowledge. Automatic footnotes were valid Markdown, but validity did not make them the requested design. The correction to plain citations was not cosmetic in the dismissive sense: it reduced visible controls and aligned connected documents without changing evidence. Conversely, a visually clean citation is not sufficient evidence of correctness. The source identity must survive renumbering or transformation. Good presentation and correct provenance are complementary tests, not competing priorities to be traded away.

The citation helper supplied a useful counterexample to blind tool compliance. It rejected the required numbered bibliography because its parser expected the helper's own representation. Changing the permanent note to satisfy the parser would have reversed the user's instruction. The bounded solution checked every source target in the actual note against the ledger, then verified an unchanged-body copy with the helper-rendered bibliography. A negative mapping control demonstrated that a reassigned source would be rejected. That verifies compatibility at the stated boundary; it does not repair the helper's separate sparse-ID allocation problem, which remains open.

This position extends, rather than contradicts, the earlier reflections on document roles and explicit completion. Their central principle was already correct: the artifact must serve its job. The missing application was choosing among research, formal assessment, learning capture and publication before a reusable skill begins. I would reconsider the implementation if mode selection repeatedly concealed material omissions or required a growing collection of exceptions. Until then, a short scope check at the existing procedure entry is preferable to another governance layer or a new mandatory report.

## R -- Reflection

### Surprise (30%)

I expected ASCII source text and legitimate Markdown syntax to be enough for a simple reference display, but the renderer produced controls the user found distracting. The surprise was the mismatch between the property I had checked and the property he cared about. I also expected the existing citation helper to accept the source format already established for knowledge notes, but it rejected the bibliography syntax rather than an evidence mapping. Those are different failures with a common lesson: a component's accepted representation is not automatically the deliverable's required representation. The research-only company request then supplied a positive contrast. Reading the frameworks could improve the questions without creating an obligation to run the full assessment. The useful distinction was visible before any score or valuation needed to be produced.

### Feel (30%)

My candid assessment is that I made Suggi supervise details that should have followed from his stated goal. Verbose source metadata, repeated cross-references and automatic footnotes were individually defensible choices, but they accumulated into a product he had not asked for. Explaining why a renderer generated the symbols was useful; it did not excuse having introduced that behavior. The eventual recovery preserved the evidence and made the examples, instructions and actual entries agree. That is concrete progress, not proof that the pattern is permanently solved. A tool kernel also supplied a scratch root different from the active profile's declared root; I moved only the newly created task directory to the correct location and added a pre-creation scope check. The mistake reinforces the need to verify an interface's actual boundary rather than trust a convenient default.

### Learn (40%)

The transferable lesson is to separate the question being asked from the machinery available to answer it. A framework can organize inquiry without producing a rating. A learning cycle can preserve a company-specific insight without manufacturing a general essay. A session closure can review completed capture without repeating it. Each result should be named for what was actually exercised, and each write should have its own scope rather than inheriting authority from the nearest workflow.

Representation changes need their own invariants. For citations, the invariant is the claim-to-source relationship; parentheses, numbering display and source-list presentation can change without changing that relationship. For verification adapters, the invariant is the original prose and evidence identity. For research scope, the invariant is honest support for the selected questions, while omitted formal assessments remain explicitly unperformed. Keeping these invariants visible is more useful than making all artifacts resemble one template.

The implementation remains modest. The company procedure now selects the requested scope before its full-report path, and the capture procedure preserves plain citations and validates a format adapter without rewriting the permanent document. These are inspectable changes at the existing points of use. Their presence does not establish autonomous operation, a completed intrinsic valuation or reliable forecasting. The next full-company task remains open because progress in evidence gathering and controlled output is not the same as resolving every cash and ownership assumption.

### One Actionable Change

Select the output contract at the start of the company-research procedure: research-only or formal assessment, requested learning outcome, and permitted write destinations. For research-only work, use framework questions but do not generate scores, valuation models or a Hub report. Before delivery, compare the actual artifacts with that selection. PASS requires supported findings and only the requested outputs and writes; HALT an added assessment, misleading completion claim or unapproved publication. This scope check is implemented in the existing profile-local skill rather than a new core-governance rule.
