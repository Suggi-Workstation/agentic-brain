# Investment Pipeline Architecture -- Automated Value Investing Research Pipeline (v2)

## Version History

| Version | Date | Author | Change |

## Problem

Suggi has a defined value investing methodology (documented in
`governance/suggi-investment-approach.md`) -- a Greenblatt-style
composite ranking of ~3,500 companies by growth, ROIC, and cheapness,
followed by manual 1-by-1 review to separate genuine bargains from
value traps, with moat analysis, management assessment, and a 30-50%
margin-of-safety threshold before any buy decision.

This is currently a manual process. At 3,500 companies, even a rapid
triage takes weeks per screening cycle. The agent team (Ava +
researcher-1 + researcher-2 + investor) has no structured pipeline to
execute this methodology. The investing/ directory in the agentic-brain
is empty. The library has foundational value-investing knowledge (moats,
margin of safety) but no mechanism to apply it systematically to real
companies.

The v1 proposal (2026-07-25) defined a 6-stage pipeline. This v2
expansion addresses gaps identified through systematic research into:
(1) current best practices for agentic financial research pipelines,
(2) what the value investing greats (Buffett, Munger, Greenblatt,
Pabrai, Sleep) would require from such a system, and (3) production
architectures deployed by FinCatch, AlphaAgents, and the CFA
Institute's recommended patterns.

## Research Foundation -- What Best Practices Say

### Agentic Workflow Patterns for Finance (CFA Institute, 2025-2026)

The CFA Institute's "Agentic AI for Finance" guide (2025-2026) is the
most authoritative source for our domain. Key findings:

- **Workflows over autonomous agents.** Finance is a tightly regulated,
  high-stakes domain. Predefined workflow patterns (prompt chaining,
  routing, parallelization, orchestrator-workers, evaluator-optimizer)
  are preferred over highly autonomous agents because they offer more
  control, predictability, and auditability.

- **The 5-component agent instruction format.** Role, Task, Constraints,
  Guidance, Response Format. Every agent in the pipeline should use this
  structure. We already adopted this in v1.

- **Evaluator-Optimizer pattern for quality.** One agent generates, a
  second evaluates and feeds back. This is the pattern behind our
  decorrelated agent design (researcher-1 + researcher-2 cross-check).
  The CFA validates this explicitly for investment research.

- **Guardrails at four layers.** System prompt, input filters, tool-call
  gatekeepers, output checks. Our pipeline should implement all four for
  every agentic stage.

- **Human-in-the-loop for high-impact decisions.** Suggi's review is the
  final gate. The CFA research confirms this is not just a safety
  measure -- it is the recommended architecture pattern for finance.

Sources: CFA Institute RPC (2025), "Agentic AI for Finance: Workflows,
Tips, and Case Studies"; Anthropic (Dec 2024), "Building Effective
Agents."

### Production Equity Research Pipeline (FinCatch, May 2026)

FinCatch built and deployed a production agentic equity research
pipeline. Their architectural decisions validate and extend our design:

- **Modular section writers, not monolithic.** Each report section
  (company overview, industry context, financial results, forecasts,
  valuation, thesis, risks, catalysts, summary) is generated by a
  separate agent call with explicit dependency ordering. This prevents
  context bloat, enables parallel execution, and creates clean retry
  boundaries.

- **Three data source types.** Deterministic (API-fetched financials),
  interpretive (Actor-Critic research agent for street expectations and
  industry context), and internal knowledge bank (graph database of
  company relationships). Our pipeline maps: Stage 0-2 = deterministic,
  Stages 3-4 = interpretive, agentic-brain = internal knowledge bank.

- **Tiered parallelism.** Tier 1 (overview, industry, results, forecasts,
  valuation) runs in parallel. Tier 2 (thesis, risks, catalysts) runs
  after Tier 1. Summary runs last. This is more granular than our v1
  design which ran only two parallel tracks (researcher-1 and
  researcher-2).

- **Deterministic assembly.** The final report is assembled
  deterministically, not by an agent. Citations are consolidated across
  sections. Status fields (section success counts, warnings) provide
  machine-readable quality signals.

Source: FinCatch Blog (May 2026), "How We Built an Agentic Equity
Research Pipeline."

### Multi-Agent Debate for Equity Analysis (AlphaAgents, Aug 2025)

The AlphaAgents paper (arXiv:2508.11152) validates multi-agent debate
for stock selection:

- **Specialist agents:** Fundamental Agent (10-K/10-Q analysis),
  Sentiment Agent (news, analyst ratings, insider trading), Valuation
  Agent (price/volume trends), Risk Agent (orchestrator).

- **Multi-round debate until consensus.** Agents exchange evidence,
  challenge each other's assumptions, and converge or flag structured
  disagreement. This is more formal than our v1 "cross-check
  disagreements" -- we should adopt a structured debate protocol.

- **Key finding:** Multi-agent debate reduces hallucination and improves
  reasoning quality. The system outperformed single-agent approaches in
  backtests.

- **Missing from our v1 design:** A dedicated sentiment/news agent. The
  AlphaAgents Sentiment Agent provides context that pure fundamental
  analysis misses -- market narrative, analyst sentiment shifts, insider
  transaction patterns.

Source: AlphaAgents (arXiv:2508.11152, Aug 2025).

### Google's 8 Multi-Agent Design Patterns (2026)

Google's Agent Development Kit guide identifies 8 fundamental patterns
built on three execution primitives (sequential, loop, parallel). The
patterns most relevant to our pipeline:

- **Sequential Pipeline:** Stages 0-1-2-3-5 follow this pattern
  naturally. Each stage's output feeds the next.

- **Parallel Fan-Out/Gather:** Stage 4 (deep dive) uses this --
  researcher-1 and researcher-2 run in parallel, outputs gathered by
  main session for cross-check.

- **Coordinator/Dispatcher:** Main session acts as coordinator,
  dispatching to specialist sub-agents at each stage.

- **Loop/Critic:** The AlphaAgents debate pattern is a Loop/Critic --
  agents iterate on analysis until consensus or structured disagreement.

Google's design principle: "Reliability comes from decentralization and
specialization. Multi-Agent Systems allow you to build the AI equivalent
of a microservices architecture."

Source: Google Developers Blog (2026), "Developers Guide to Multi-Agent
Patterns in ADK."

### Architecture Design Principles (StackAI 2026 Guide)

The StackAI 2026 guide identifies four architecture types (single agent,
hierarchical, sequential pipeline, decentralized swarm) and provides
this critical rule: "Add autonomy in layers: single agent first, then
hierarchical or pipeline, then swarm if you truly need it."

Our pipeline is a hybrid: sequential pipeline with a hierarchical
orchestrator-workers step in the middle (Stages 3-4). This is the
recommended pattern for complex workflows.

The guide also emphasizes: "Invest in foundations that survive model
changes. Clean tool boundaries. Clear permissions. Strong traces. A
small evaluation set." Our pipeline should include an evaluation harness
from day one.

Source: StackAI (Jan 2026), "The 2026 Guide to Agentic Workflow
Architectures."

## Value Investor Alignment -- What the Greats Would Say

### Buffett & Munger

**Alignment:** The screening methodology (growth + ROIC + cheapness
composite) is fundamentally aligned with Buffett's criteria: predictable
earnings (growth stability), high returns on capital (ROIC as quality
proxy), conservative financing, and margin of safety. Buffett's
systematic approach has been successfully translated into quantitative
strategies -- Interactive Brokers published a 3-stage quantitative
Buffett strategy (identify Buffett-type companies via earnings
predictability + ROIC + conservative financing, then value with DCF +
EPV, then build portfolio).

**What they would demand:**

1. **Moat analysis cannot be automated away.** Buffett's most important
   criterion -- durable competitive advantage -- requires deep business
   understanding. Our pipeline correctly keeps this in the agent-judgment
   stages (3-4), but the moat analysis framework must be comprehensive.
   The v1 pipeline uses the Morningstar 5-source framework. This should
   be expanded to include: switching costs, network effects, intangible
   assets, cost advantages, efficient scale, AND the Sleep/Zakaria
   "scale economies shared" subtype.

2. **Management quality is paramount.** Buffett: "We look for three
   things: intelligence, energy, and integrity. Without the first two,
   the third will kill you." Our pipeline checks for insider ownership
   (skin in the game) but should also assess: capital allocation track
   record (buybacks at what price, acquisitions at what multiple),
   candor in shareholder letters, and whether management thinks like
   owners.

3. **Circle of competence must be explicit.** Buffett only invests in
   businesses he understands. The pipeline should flag when a company
   falls outside known domains and require Suggi's explicit approval
   to proceed. The "too hard" pile is a feature, not a failure.

4. **Invert, always invert (Munger).** The pipeline should explicitly
   screen for what to AVOID, not just what to buy. Stage 3 (exclusion
   filtering) does this partially, but it should be expanded with
   Munger's "psychology of human misjudgment" red flags: promotional
   management, excessive acquisition activity, serial restructurings,
   and businesses that require constant genius to succeed.

### Joel Greenblatt (Magic Formula)

**Alignment:** Our composite ranking (25% growth, 25% ROIC, 50%
cheapness) is directly derived from and improves upon Greenblatt's
dual-factor rank (earnings yield + return on capital). Greenblatt's
formula uses two factors; Suggi's uses three, adding an explicit growth
dimension.

**Key Greenblatt insight:** "The magic formula works because it forces
discipline." The biggest enemy of value investing is behavioral --
abandoning the strategy during drawdowns. Our pipeline enforces
discipline structurally: every company is evaluated against the same
criteria, every cycle. No fatigue, no mood, no "I'll skip this one."

Greenblatt's formula is mechanical (buy top 20-30 ranked, hold 1 year,
sell, repeat). Suggi's approach goes further by adding qualitative
layers (moat, management, deep dive). This is a hybrid: Greenblatt's
quantitative discipline with Buffett's qualitative depth. Optimal.

**Implementation note:** Greenblatt himself acknowledges the formula's
limitation -- it populates with "deeply out-of-favor, structurally
challenged businesses." The qualitative layers (Stages 3-4) are what
separate the genuine bargains from the value traps. This is exactly
Suggi's process: sort by composite rank, then walk the list one by one
to separate cheap-and-good from cheap-because-bad.

### Mohnish Pabrai (Dhandho)

**Alignment:** Pabrai's "Heads I win, tails I don't lose much" maps
directly to our margin-of-safety requirement (30-50%). His investment
process: (1) search for undervalued businesses via screens (low P/E,
52-week lows, spinoffs), (2) deep research to determine intrinsic value,
(3) buy only at significant discount, (4) use checklists before every
purchase.

**What's missing from our pipeline:**

1. **Pabrai's 7-Question Pre-Purchase Checklist.** Before any BUY
   CANDIDATE decision, these questions must be answered:
   - Is this business within my circle of competence?
   - Does it have a durable competitive advantage?
   - Is management able and honest (skin in the game)?
   - Is the balance sheet strong (low/no debt preferred)?
   - Is the business simple and predictable?
   - Is there a catalyst for value realization?
   - What is the margin of safety?

2. **Kelly Formula / Position Sizing.** Pabrai uses "quarter-Kelly" for
   position sizing -- bet 25% of what full Kelly would suggest, providing
   a margin of safety on the bet size itself. Our pipeline currently has
   no position sizing logic. This should be Stage 6.

3. **"Invest in copycats, not innovators."** Pabrai prefers businesses
   with proven models over unproven innovation. The pipeline should flag
   companies with unproven business models for higher scrutiny.

4. **"Invest in simple businesses."** If the business requires a PhD to
   understand, Pabrai passes. The pipeline should note complexity as a
   risk factor.

### Nick Sleep & Qais Zakaria (Nomad Partnership)

**Alignment:** Sleep/Zakaria's concentrated portfolio (6-8 positions
held for years) and focus on "destination analysis" is the deepest level
of value investing. Their framework adds dimensions our v1 pipeline
completely missed.

**Critical additions needed:**

1. **Destination Analysis.** Sleep's most distinctive contribution:
   "When we think of our investee companies, the firms which we would
   quite happily own with no word from them for years are those
   businesses in which we have the highest confidence of reaching a
   favourable destination." This is NOT a 3-5 year DCF. It is a 10+
   year projection of what the business will look like, what its moat
   will be worth, and whether it will be stronger or weaker than today.
   This should be a dedicated stage between deep dive and valuation.

2. **"Scale Economies Shared" Moat Subtype.** Sleep/Zakaria identified
   a moat pattern missed by the standard Morningstar framework:
   companies that achieve scale economies and share the benefits with
   customers (lower prices) rather than shareholders (higher margins).
   This creates a self-reinforcing cycle: lower prices -> more customers
   -> greater scale -> even lower prices. Amazon, Costco, GEICO. Our
   moat framework should explicitly include this subtype.

3. **Concentration Conviction.** Sleep held 6-8 stocks. He argued
   "owning more stocks does not lower risk but raises it" because
   knowledge is the source of value added. Our pipeline should support
   concentrated portfolio construction -- not 50 "BUY CANDIDATE"
   outputs, but the best 5-8 with the highest conviction.

4. **"Control the Urge for Action."** Sleep: "The decision not to do
   something is still an active decision." The pipeline should explicitly
   support inactivity -- most screening cycles should produce ZERO new
   buys. This is a feature, not a failure. The default output should be
   "nothing to do" unless a truly exceptional opportunity emerges.

### Synthesis: What the Greats Agree On

Despite their different styles, six principles are universal:

1. **Screen broadly, then go deep.** All of them use quantitative screens
   as a first pass, then qualitative deep dives for the survivors.

2. **Moat is everything.** Every single one identifies durable
   competitive advantage as THE critical factor. No moat = no
   investment.

3. **Management matters enormously.** Owner-orientation, capital
   allocation skill, integrity. No amount of cheapness compensates for
   bad management.

4. **Margin of safety is non-negotiable.** 30-50% discount to intrinsic
   value. Without it, you are speculating, not investing.

5. **Concentrate on your best ideas.** 5-15 positions, not 50-100.
   Diversification is protection against ignorance.

6. **Patience is the ultimate edge.** Most screening cycles should
   produce nothing. Forced action destroys returns. "The stock market is
   a device for transferring money from the impatient to the patient."

## Proposed Solution -- 10-Stage Pipeline (v2)

The v1 proposal defined 6 stages (0-5 + knowledge compounding as Stage
6). The v2 pipeline expands to 10 stages, incorporating every finding
from the research and value-investor analysis above. Stages are grouped
into four phases: Screening (deterministic), Triage (agentic), Deep
Analysis (agentic, decorrelated), and Decision (synthesis + monitoring).

### Phase A: Screening (Deterministic -- Python, No LLM)

#### Stage 0: Data Ingestion

Pull financial data for the target universe (e.g., ~3,500 EU companies,
or S&P 500 for US pilot).

Data collected per company: revenue (5-10 years), EBIT/operating income,
FCF, ROIC, ROE, enterprise value, market cap, P/E, P/S, P/FCF, P/EBIT,
total debt, debt/equity, debt/EBITDA, current ratio, insider ownership
percentage, industry/sector classification, market cap category (large/
mid/small/micro), country, exchange.

Data sources: SEC EDGAR (US, free), Financial Modeling Prep or EODHD
(EU, paid ~$30/month). Cross-validate key metrics against at least two
sources for the top-ranked companies.

**NEW in v2 -- Data quality validation sub-stage (Stage 0.5):**
Before any ranking, flag and handle:
- Negative enterprise values (possible data error or net cash company)
- Missing data fields (exclude from ranking, flag for investigation)
- Stale data (>90 days since last reported period)
- Extreme outliers (>5 standard deviations from sector median)
- Companies with restated financials (flag for extra scrutiny)
- Survivorship bias note (delisted companies excluded from historical
  analysis -- document this as a known limitation)

Output: Clean, validated dataset with quality flags per company.

#### Stage 1: Sector-Aware Composite Ranking

**NEW in v2 -- Sector-specific metrics.** Different sectors require
different growth and quality metrics. The v1 pipeline treated all
companies identically. v2 adds sector-classification routing:

| Sector | Growth Metric | Quality Metric | Cheapness Metric |
|:--|:--|:--|:--|
| Industrial/Consumer | Revenue CAGR (5-10yr) | ROIC | EV/EBIT |
| Financial (Banks) | Book Value Growth | ROE | P/B |
| Financial (Insurance) | Premium Growth | Combined Ratio | P/B |
| Technology (SaaS) | Revenue CAGR | Rule of 40 (Rev Growth + FCF Margin) | EV/Revenue |
| REITs | FFO/Share Growth | ROE | P/FFO |
| Energy/Materials | Production Volume Growth | ROCE | EV/EBITDA |
| Healthcare (Pharma) | Revenue CAGR | ROIC | EV/EBIT |
| Default | Revenue CAGR | ROIC | EV/EBIT |

Composite ranking (same weights as v1):
- Growth: 25% weight (percentile rank within sector)
- Quality (ROIC/ROE/sector metric): 25% weight
- Cheapness (EV/EBIT or sector equivalent, lower = better): 50% weight

Composite = 0.25 * growth_rank + 0.25 * quality_rank + 0.50 *
cheapness_rank. Sort ascending. Deterministic. Pure math.

#### Stage 2: Broad Screen Filtering

Walk the ranked list 1-by-1. A company must meet BOTH thresholds:
- CAGR growth >=10% over 5-10 years (using sector-appropriate metric)
- ROIC >=15% and/or ROE >=15% (using sector-appropriate metric)

Companies meeting both thresholds enter the "broad screen result."
Deterministic threshold checks. No LLM.

For MVP: tightened thresholds (CAGR >=15%, ROIC >=20%) reduce the result
set to 20-50 candidates, keeping agent processing manageable.

### Phase B: Triage (Agentic -- Sequential)

#### Stage 3: Exclusion Filtering (Agent-Assisted)

For each company in the broad screen result, evaluate against explicit
exclusion criteria. This stage is deterministic where possible, agentic
where judgment is required.

**3A. Deterministic exclusions (auto-DISCARD, no agent needed):**
- P/E > 40, P/S > 5, P/FCF > 30, P/EBIT > 25 (configurable thresholds)
- Debt/EBITDA > 4x (or > 3x for cyclicals)
- Debt/Equity > 1.5 (or > 1.0 for financials -- use regulatory capital
  ratios instead)
- Negative free cash flow for 3+ consecutive years
- Market cap < $50M (micro-cap liquidity risk)

**3B. Moat assessment (agent judgment -- researcher-1):**
- Does the company have a clearly identifiable moat?
- Which of the 6 moat sources: (1) switching costs, (2) network effects,
  (3) intangible assets, (4) cost advantages, (5) efficient scale, (6)
  scale economies shared (Sleep/Zakaria subtype)?
- How durable is it? (Weak/Narrow/Wide, with evidence)
- The agent MUST cite specific evidence for each moat claim.

**3C. Management assessment (agent judgment -- researcher-2):**
- Insider ownership >=5%? (Skin in the game)
- Capital allocation track record: buybacks at what valuation, M&A at
  what multiple, dividend policy consistency
- Shareholder communication quality (candor in annual letters)
- Tenure and stability of management team
- Any history of value-destructive decisions?

**3D. Cheap-and-good vs cheap-because-bad (agent synthesis):**
The critical triage. Both researchers produce independent verdicts:
- PASS: Genuinely out of favor, business quality intact
- WATCHLIST: Good business but too expensive right now
- DISCARD: Correctly cheap for structural reasons (declining industry,
  broken business model, terminal disruption)

**Agent instruction design (CFA 5-component format):**

```
Role: Value investor, Buffett-Graham-Munger school. Expert in moat
analysis (6-source framework including scale-economies-shared) and
value trap detection.

Task: Evaluate {TICKER} ({RANK} of {TOTAL} in composite screen).
Growth: {GROWTH}%, ROIC: {ROIC}%, EV/EBIT: {MULTIPLE}x. Sector:
{SECTOR}. Determine: PASS (deep dive worthy), WATCHLIST (good but
expensive), or DISCARD (cheap for structural reasons).

Constraints:
- Every moat claim MUST cite specific evidence with source URLs.
- Flag accounting red flags (growing DSO, aggressive revenue
  recognition, frequent restatements).
- Auto-DISCARD if debt/EBITDA > 4x without structural justification.
- If company falls outside known circle of competence, flag TOO HARD.
- Do not recommend PASS if you cannot explain the business in 3
  sentences.

Guidance:
1. web_search: "{TICKER} competitive advantage moat"
2. web_search: "{TICKER} management insider ownership"
3. web_fetch: latest 10-K/annual report
4. brain-index: prior analysis on {TICKER} or {SECTOR} industry
5. web_search: "{TICKER} accounting red flags controversy"

Response Format: Structured JSON with verdict, moat classification,
evidence array with source URLs, management score (1-10), key risk
flags, and 3-5 sentence narrative.
```

Output per company: PASS (to Phase C), WATCHLIST (to Phase D monitoring),
or DISCARD (with structured reason in investing.log).

**Decorrelated execution:** researcher-1 and researcher-2 evaluate
independently. Main session compares verdicts:
- Both PASS -> proceed to Stage 4
- Both DISCARD -> log and move on
- Disagreement -> Stage 3E debate round
- One or both WATCHLIST -> add to watchlist, monitor price

**NEW in v2 -- Stage 3E: Structured debate protocol (AlphaAgents
pattern):**
When researchers disagree, each produces a rebuttal addressing the
other's evidence. Maximum 2 debate rounds. If consensus is not reached,
escalate to Suggi with both analyses and the specific points of
disagreement. Document the disagreement in investing.log.

### Phase C: Deep Analysis (Agentic -- Decorrelated, Parallel)

#### Stage 4: Deep Dive (Parallel Fan-Out)

For each PASS company (typically 10-25 from a full screen, 3-8 with
tightened MVP thresholds), two independent analyses run in parallel:

**4A. Moat & Competitive Dynamics (researcher-1):**
- Full moat durability assessment using the expanded 6-source framework
- Industry competitive positioning (Porter's Five Forces, market share
  trends, disruption risk)
- Customer value proposition analysis
- Threat horizon: how many years of protected returns remain?
- Competitor benchmarking (top 3-5 competitors by market share,
  compare margins, growth, returns on capital)
- **NEW in v2 -- Destination analysis (Nick Sleep):** Project the
  business 10+ years forward. What will this company look like? Will
  its moat be wider or narrower? What must go right (and wrong) for
  the favourable destination to materialize?

**4B. Financial Health & Red Flags (researcher-2):**
- Normalized earnings (adjusting for unusual items, cycles)
- Free cash flow conversion quality (FCF/Net Income ratio, 5-year
  trend)
- Debt structure analysis (maturity ladder, fixed vs floating, covenant
  headroom)
- Return on incremental invested capital (how well does the company
  deploy new capital?)
- **NEW in v2 -- Structured red flag scan (explicit checklist):**
  - Earnings quality: growing DSO, DSI divergence, aggressive revenue
    recognition, serial "one-time" charges
  - Balance sheet: goodwill > 50% of assets, off-balance-sheet items,
    pension underfunding
  - Cash flow: persistent gap between reported earnings and FCF,
    working capital deterioration
  - Governance: related-party transactions, dual-class shares with poor
    alignment, frequent auditor changes
  - Munger psychology flags: promotional management language, excessive
    M&A ("empire building"), serial restructuring charges

**4C. Sentiment & Market Context (NEW in v2 -- researcher-2 additional
scope, or dedicated sub-agent):**
- News sentiment analysis (last 12 months of major news, analyst rating
  changes)
- Insider transaction patterns (significant buying = positive signal,
  significant selling = red flag)
- Short interest and trend (elevated short interest may indicate hidden
  problems or opportunity)
- Institutional ownership trends
- Earnings surprise history (consistently beating or missing?)
- Market narrative: what story is the market telling about this company,
  and is it accurate?

**Disagreement resolution:** Same as Stage 3E -- debate protocol, max 2
rounds, escalate unresolved disagreements to Suggi.

Output per company: structured deep-dive report with moat assessment,
financial health score, red flag inventory, sentiment context, and a
confidence score (1-10). Both researcher outputs are preserved for
auditability.

#### Stage 5: Investment Thesis Formulation (NEW in v2)

Before valuation, formulate an explicit investment thesis. This stage
crystallizes why this company might be a good investment in 3-5
testable pillars.

Each pillar must be:
- **Specific:** "Company X will grow revenue at 8%+ CAGR for 5 years
  because product Y is gaining share in a growing market Z."
- **Falsifiable:** A future data point that would disprove it (e.g.,
  "If market Z growth drops below 3%, this pillar breaks.")
- **Monitored:** Each pillar maps to a monitoring metric with update
  cadence.

The thesis also includes:
- **Key risks** with impact pathways (not generic disclaimers).
  "If competitor A launches product B by Q3 2027, company X could lose
  200 bps of market share, reducing revenue growth to 3%."
- **Catalysts** to monitor: upcoming product launches, regulatory
  decisions, earnings inflection points, potential spinoffs or
  restructuring.
- **Variant perception:** What does the market believe that we believe
  is wrong? What do we see that the market misses? Without a variant
  perception, there is no edge.

This stage can be executed by the main session or researcher-1, using
the deep dive outputs from Stage 4 as evidence.

Source: FinCatch (2026) -- "A clear thesis with a small number of
testable pillars." Also validated by CFA Institute's Case Study 1
(fundamental assessment workflow).

### Phase D: Decision (Valuation + Synthesis)

#### Stage 6: Valuation (Investor Sub-Agent)

The investor sub-agent produces:

**6A. DCF Model:**
- Bull/Base/Bear scenarios with explicit assumptions
- Revenue growth path, margin path, reinvestment assumptions, terminal
  growth rate
- Sector-appropriate methodology (auto-selected by industry
  classification):
  - Generic: 2-stage DCF (5-year explicit + terminal value)
  - SaaS: revenue-based DCF with churn/CAC/LTV parameters
  - REIT: FFO/AFFO multiple + NAV
  - Bank: excess returns model (ROE - COE * Book Value)
  - Insurance: combined ratio + float value + investment portfolio
  - Energy/Materials: cycle-normalized earnings + reserve valuation

**6B. Earnings Power Value (EPV):**
- Cross-check against DCF. Significant divergence requires explanation.
- EPV = Adjusted Earnings / Cost of Capital (no growth assumption).
  This is the "no-growth floor" -- if the stock trades below EPV,
  growth comes free.

**6C. Multiple-Based Sanity Check:**
- Compare current multiples (P/E, EV/EBIT, P/B) against 5-year
  historical range and industry peers.
- Is the market pricing this as if it is in decline? Growth? Recovery?
  Does the multiple narrative match the fundamental narrative?

**6D. Margin of Safety Calculation:**
- Intrinsic value range (bull-base-bear weighted average, with base
  case getting highest weight)
- Current MOS = 1 - (Market Price / Intrinsic Value Base Case)
- Classification:
  - MOS >= 30%: BUY CANDIDATE
  - MOS >= 20% and < 30%: WATCHLIST (monitor for price decline)
  - MOS < 20% but strong moat: WATCHLIST (track for entry)
  - Fails any exclusion: DISCARD

#### Stage 7: Investment Checklist Gate (NEW in v2)

Before any BUY CANDIDATE classification is finalized, the full
investment checklist must be applied. This synthesizes Pabrai's
7-question checklist with Buffett/Munger/Sleep criteria:

- [ ] **Circle of competence:** Do I understand this business well enough to
  project its destination 10 years out? If not, TOO HARD pile.
- [ ] **Durable moat:** Is the competitive advantage widening, stable, or
  narrowing? Evidence from Stage 4A.
- [ ] **Able and honest management:** Skin in the game? Intelligent capital
  allocation? Candor in communication? Evidence from Stage 3C.
- [ ] **Strong balance sheet:** Can the company survive a 2-year
  recession without raising capital? Debt structure analysis from
  Stage 4B.
- [ ] **Simple and predictable:** Can a reasonably intelligent person
  understand this business in 30 minutes? If not, flag complexity
  premium.
- [ ] **Favourable destination:** Where is this business in 10+ years?
  Does the destination analysis (Stage 4A) support conviction?
- [ ] **Margin of safety >= 30%:** From Stage 6D. If MOS is below
  threshold, the company goes to WATCHLIST regardless of quality.
- [ ] **No fatal red flags:** Any Stage 4B red flags that are dealbreakers?
  (Fraud indicators, terminal disruption, unrecoverable balance sheet.)
- [ ] **Patience check:** Is this the best available opportunity RIGHT
  NOW, or am I buying because I am bored? If forced, HALT.

This checklist is executed by the main session, synthesizing all prior
stages. Every answer MUST cite evidence from Stages 3-6. A "yes" without
evidence is a FAIL.

#### Stage 8: Position Sizing (NEW in v2)

If the company passes all checklist items and is classified BUY
CANDIDATE, determine position size using the Kelly-inspired Dhandho
framework:

**Pabrai's Quarter-Kelly approach:**
1. Estimate edge: (Intrinsic Value - Market Price) / Intrinsic Value
   (this is our MOS, already calculated)
2. Estimate probability of being right: confidence score from Stage 4
   synthesis (1-10, where 10 = maximum conviction)
3. Convert to Kelly fraction: f = edge * confidence_factor
4. Quarter-Kelly: position_size = f * portfolio_value * 0.25

**Position size caps:**
- Maximum single position: 15% of portfolio (Sleep/Zakaria cap)
- Maximum sector exposure: 30% of portfolio
- Maximum geography exposure: configurable by region
- Minimum position size: 3% (below this, not worth the research effort)

**Portfolio context:**
- How many existing positions? If already at 8+ positions (Sleep
  concentration limit), new buys must replace or wait for attrition.
- Correlation with existing holdings (avoid doubling up on same factor
  exposure).
- Tax considerations (jurisdiction-dependent, deferred to Suggi).

Note: Position sizing is a recommendation, not an execution. Suggi
makes the final allocation decision.

### Phase E: Compounding & Monitoring

#### Stage 9: Knowledge Compounding

Write outputs to the agentic-brain. Every artifact is structured,
searchable, and cross-referenced:

**Files written:**

- `investing/watchlist.md`: Updated with tiered list:
  - TIER 1: BUY CANDIDATES (MOS >= 30%, all checklist items PASS)
  - TIER 2: WATCH (MOS >= 20%, strong moat -- monitor for price decline)
  - TIER 3: MONITOR (Good business, too expensive -- track for entry)
  - Each entry includes: ticker, sector, current price, intrinsic value
    range, MOS, thesis summary (1 sentence), last updated date.

- `investing/companies/{TICKER}.md`: Full deep-dive analysis with:
  - Company overview and industry context
  - Moat assessment (6-source framework, durability, destination)
  - Financial health analysis with normalized earnings and red flags
  - Management assessment and capital allocation track record
  - Investment thesis with testable pillars and falsification conditions
  - DCF valuation with bull/base/bear scenarios and methodology
  - EPV cross-check
  - Margin of safety calculation
  - Risk inventory with impact pathways
  - Catalysts to monitor
  - Sentiment context
  - Full source citations (URLs, filing references)

- `investing/theses/{TICKER}-thesis.md`: Condensed thesis (1 page):
  - 3-5 testable pillars with falsification conditions
  - Key risks and catalysts
  - MOS and intrinsic value range
  - Update cadence and monitoring metrics

- Library topic: If novel industry or competitive insight emerges from
  the analysis, write to `library/value-investing/` or appropriate
  domain anchor.

- IOR reflection: Durable investment insight from the analysis

- `investing.log`: Entry recording the full analysis with ENT-ID,
  including all stage outputs, agent verdicts, debate resolution, and
  final classification.

- Brain-index rebuilt for future retrieval.

#### Stage 10: Continuous Monitoring (NEW in v2)

Companies that enter the watchlist or portfolio are tracked between full
screening cycles:

**10A. Watchlist Price Monitoring (automated, monthly):**
- For each WATCHLIST company: recalculate MOS against current price
- If MOS crosses >=30% threshold: flag for Suggi review
- If MOS drops below 10%: flag for thesis re-evaluation
- Deterministic. No LLM.

**10B. Quarterly Earnings Review (per company, when earnings release):**
- Fetch latest 10-Q/10-K
- Recalculate key metrics (revenue growth, margins, ROIC, debt ratios)
- Check against thesis pillars: is each pillar still intact?
- Update MOS with latest financials
- Agent produces a 1-page earnings update note with:
  - What changed vs thesis expectations?
  - Any pillar falsified? If so, recommendation (HOLD/SELL/RE-EVALUATE)
  - Updated MOS
- Output: appended to `investing/companies/{TICKER}.md` as dated entry

**10C. Event-Triggered Reviews (when applicable):**
- Significant insider buying/selling (>$500K for large caps, >$100K for
  small caps)
- Major M&A announcement
- Regulatory action or investigation
- Management change (CEO/CFO departure)
- Thesis-breaking news (product failure, competitor entry, regulatory
  change)
- Agent scans news weekly for trigger events on watched/held companies

**10D. Annual Full Re-Screen:**
- Full pipeline run (Stages 0-8) on the entire universe
- Existing watchlist/portfolio positions get priority analysis
- New screening cycle adds fresh candidates
- Old analyses (12+ months) on non-held companies are archived

### Execution Model

**Full Screen Cycle (cron-triggered, quarterly):**
Stages 0-8 run as a coordinated pipeline. Cron jobs detailed below.
Output written to brain. Suggi reviews all BUY CANDIDATE outputs.

**Single-Ticker Mode (on-demand):**
Suggi asks "Analyze {TICKER}." Pipeline starts at Stage 3 (exclusion
filtering) or Stage 4 (deep dive), using API-fetched data for that
single company. All subsequent stages run as normal.

**Watchlist Maintenance (cron-triggered, monthly):**
Stage 10A-10C only. Updates MOS, flags threshold crossings.

## Job Architecture -- 4 Cron Jobs

The research validates splitting the pipeline into separate,
independently-scheduled cron jobs rather than one monolithic run.
This follows the Google ADK principle: "specialization and
decentralization for reliability."

Each job has independent failure boundaries -- a failure in one does
not cascade to others.

### Job 1: Data Ingestion + Screening (owned by investor)

**Schedule:** Monthly (first weekend of month), or quarterly aligned
with earnings seasons (Feb, May, Aug, Nov -- after most 10-K/10-Q
filings).

**Type:** Python script + OpenClaw cron.

**What it does:** Stages 0-2. Data pull, quality validation, sector
classification, composite ranking, broad screen filtering. Pure
Python. No LLM calls. No agent spawns.

**Output:** CSV file written to `investing/data/{DATE}-screen-results.csv`
in the brain, containing ranked list with all metrics, quality flags,
and PASS/FAIL for broad screen thresholds. Also writes a summary
JSON with universe stats (total companies, pass count, sector
breakdown).

**Estimated runtime:** 5-15 minutes for 3,500 companies (API-dependent).

**Failure mode:** If data API is down, job retries in 6 hours. If data
quality issues detected (e.g., >20% missing fields), alert Suggi and
HALT -- do not proceed to agent stages with bad data.

### Job 2: Broad Screen Agent Review (owned by main)

**Schedule:** Triggered after Job 1 completes successfully (sequential
dependency). For MVP with tightened thresholds (20-50 candidates): runs
immediately. For full scale (100-300 candidates): batches of 25 per run,
spread across 1-2 weeks to manage token costs.

**Type:** Agent-turn cron job on main session.

**What it does:** Stage 3 only. For each broad-screen company, spawns
researcher-1 and researcher-2 sub-agents for parallel exclusion
filtering (moat, management, cheap-vs-bad triage). Main session
orchestrates: dispatch, gather, compare verdicts, trigger debate rounds
if needed, produce final PASS/WATCHLIST/DISCARD classification.

**Output per company:** Structured JSON verdict written to brain.
WATCHLIST entries added to `investing/watchlist.md`. DISCARD reasons
logged to `investing.log`. PASS companies queued for Job 3.

**Token cost:** ~$0.30-0.80 per company (CFA benchmark). At 50
candidates: ~$15-40 per cycle. At 200 candidates: ~$60-160 per cycle.

**Batching strategy for full scale:** Process top-N by rank. First
batch = top 25. If sufficient BUY CANDIDATES emerge (3-5+), pause
remaining batches for Suggi review. If insufficient, continue next
batch. This implements the value investor principle: you only need a
few good ideas.

### Job 3: Deep Analysis Pipeline (owned by main)

**Schedule:** Triggered after each batch of Job 2 completes.

**Type:** Agent-turn cron job on main session.

**What it does:** Stages 4-8. For each PASS company:
1. Stage 4: Spawn researcher-1 (moat + destination analysis) and
   researcher-2 (financial health + red flags + sentiment) in parallel.
   Gather outputs, debate if needed.
2. Stage 5: Formulate investment thesis with testable pillars.
3. Stage 6: Spawn investor sub-agent for DCF + EPV + MOS.
4. Stage 7: Apply investment checklist gate.
5. Stage 8: Calculate position sizing recommendation (if BUY
   CANDIDATE).

**Output:** Full company analysis files written to
`investing/companies/{TICKER}.md`. Thesis file written to
`investing/theses/{TICKER}-thesis.md`. Watchlist updated. investing.log
entry.

**Token cost:** ~$1.00-2.50 per deep-dive company. At 5-15 PASS
companies per cycle: ~$5-38.

### Job 4: Watchlist Maintenance (owned by investor)

**Schedule:** Monthly (mid-month, between full screen cycles).

**Type:** Python + light agent-turn.

**What it does:** Stages 10A-10C.
- 10A (deterministic): Recalculate MOS for all watchlist entries against
  current prices. Flag threshold crossings.
- 10B (deterministic check, agentic if earnings released): For companies
  that reported earnings since last check, fetch new financials and run
  thesis pillar check.
- 10C (agentic): Scan news for trigger events on watchlist + portfolio
  companies. Flag significant events for Suggi review.

**Output:** Updated MOS values in watchlist. Earnings update notes
appended to company files. Event flags sent to Suggi (via system event).

**Token cost:** Minimal for watchlist-only mode (~$2-5/month).

### Cron Job Summary

| Job | Owner | Schedule | Type | Stages |
|:--|:--|:--|:--|:--|
| Data + Screen | investor | Monthly/Quarterly | Python | 0-2 |
| Agent Review | main | After Job 1 | Agent-turn | 3 |
| Deep Analysis | main | After Job 2 | Agent-turn | 4-8 |
| Watchlist | investor | Monthly | Python + Agent | 10 |

All four jobs log to `investing.log`. All output files committed to
agentic-brain. Brain-index rebuilt after each full cycle completes.

## Impact

### Positive

- **Coverage:** Systematic triage of 3,500 companies becomes feasible.
  The deterministic screening (Stages 0-2) reduces 3,500 to 20-200
  candidates in minutes. The agent processes 10-25 deep-candidates per
  cycle rather than Suggi manually reviewing hundreds.

- **Depth:** The v2 pipeline adds 4 stages the greats would demand:
  thesis formulation (testable, falsifiable), investment checklist
  (Pabrai/Buffett synthesis), destination analysis (Sleep/Zakaria),
  and position sizing (Kelly/Dhandho). Each addresses a dimension v1
  missed.

- **Consistency:** Every company evaluated against the same framework.
  No fatigue bias. No "I am tired of looking at screeners." The
  checklist gate ensures no criteria are skipped when attention wanes.

- **Decorrelation payoff:** Two independent agent perspectives
  cross-check each other at the critical triage point (Stage 3) and
  deep dive (Stage 4). Structured debate protocol (AlphaAgents pattern)
  resolves or escalates disagreements. The system catches what a single
  agent would miss.

- **Compounding:** Every analysis permanently enriches the brain. A
  company analyzed in Q1 2027 is retrievable via brain-index in Q3 2029.
  Industry patterns accumulate across analyses. The knowledge base
  compounds.

- **Sector-specific accuracy:** v2's sector-routed metrics prevent the
  ranking system from penalizing asset-light SaaS companies for low
  EV/EBIT or rewarding over-leveraged banks for high ROIC. Each sector
  gets appropriate metrics.

- **Patience enforcement:** The explicit checklist question "Is this the
  best available opportunity RIGHT NOW, or am I buying because I am
  bored?" and the Sleep/Zakaria "urge for action" control gate prevent
  the most common value investing failure: doing something when nothing
  is the correct action.

- **Auditability:** Every decision logged in `investing.log`. Every
  analysis has source citations. MOS calculations are reproducible. If
  a decision proves wrong in 3 years, the full decision trail is
  preserved for post-mortem.

### Risk

- **Hallucination in qualitative stages:** Moat, management, and
  sentiment assessment can produce confident-sounding but incorrect
  analysis. Mitigations: (a) every moat/management claim requires a
  source URL, (b) structured debate protocol forces evidence-based
  disagreement resolution, (c) checklist gate requires evidence for
  every answer, (d) Suggi reviews all BUY CANDIDATE outputs, (e)
  the "TOO HARD" classification is an explicit escape hatch -- if
  evidence is insufficient, the agent MUST say so rather than
  fabricate.

- **API data quality:** Free financial data APIs may have stale or
  incorrect data, producing wrong rankings. Stage 0.5 (data quality
  validation) partially mitigates this, but the fundamental limitation
  remains. Mitigation: (a) cross-check key metrics against at least
  two sources for top-ranked companies, (b) start with SEC EDGAR (US,
  high-quality, free) for pilot, (c) for EU, validate a small verified
  sample before trusting the pipeline at scale.

- **Over-automation:** The agent could miss qualitative red flags that
  Suggi would catch. Mitigation: the pipeline is a research tool, not
  a trading system. Suggi's review is the final gate. No automated
  execution. The checklist and debate protocol are designed to surface
  disagreements, not bury them.

- **Pipeline complexity:** Ten stages across 4 cron jobs creates
  failure points. Mitigation: (a) deterministic stages (0-2, 10A) are
  independent of agentic stages, (b) each cron job has independent
  failure boundaries, (c) single-ticker mode bypasses the full
  pipeline for on-demand analysis, (d) follow Anthropic's principle:
  test each stage in isolation before chaining.

- **Token cost at scale:** Full pipeline on 200 broad-screen candidates
  could cost $100-200+ per quarterly cycle. Mitigation: (a) start with
  tightened thresholds for MVP (20-50 candidates, $10-40/cycle), (b)
  batch processing with pause-after-N for Suggi review, (c) only run
  deep analysis (most expensive stages) on companies that survive
  Stage 3 filtering.

- **Look-ahead and survivorship bias:** Backtesting the screening
  methodology is compromised by both. Companies that went bankrupt are
  not in today's datasets. Historical financial data may include
  information not available at the time. Mitigation: document as known
  limitation. Use point-in-time data where available. Do not make
  claims about "historical performance" of the screening methodology.

### Cost

- **Data API:** $0 for US pilot (SEC EDGAR free). ~$30/month for EU
  data when scaling (Financial Modeling Prep or EODHD).

- **LLM tokens:** ~$0.30-0.80 per Stage 3 company (broad screen review),
  ~$1.00-2.50 per Stage 4-8 company (deep analysis). At 20-30 PASS
  companies per quarterly cycle: ~$25-75 per cycle. At full scale (100+
  candidates): ~$80-250 per cycle, mitigated by batching and Suggi
  review pauses.

- **Implementation effort:**
  - Phase 1 (MVP, 2-4 weeks): Single-ticker mode (Stages 3-8), Python
    screening script (Stages 0-2 for US), job architecture.
  - Phase 2 (Full pipeline, 2-4 weeks): Cron automation, EU data
    integration, watchlist monitoring (Stage 10).
  - Phase 3 (Optimization, ongoing): Evaluation harness, sector-specific
    refinements, debate protocol tuning.

- **Maintenance:** Low after initial build. The pipeline uses existing
  agent infrastructure (sub-agents, cron, brain). No new services, no
  new repos, no deployment complexity beyond the VPS.

## Open Questions

1. **Data API choice:** Financial Modeling Prep ($29/month, 250
   requests/day) vs EODHD ($30/month, 100K requests/month) vs Alpha
   Vantage (free tier, 25 requests/day). Which has the best EU
   small/mid-cap coverage? Suggi's preference?

2. **MVP scope and timeline:** Phase 1 (single-ticker pipeline + US
   screening) vs Phase 2 (full cron pipeline + EU data). Recommendation:
   build Phase 1 on 2-3 known tickers to validate the pipeline end-to-end
   before investing in cron automation and EU data.

3. **Cron schedule:** Quarterly (aligned with earnings seasons: Feb,
   May, Aug, Nov) or monthly? Quarterly matches the data refresh cycle
   and keeps costs manageable. Monthly provides faster idea flow but
   risks analyzing stale financials. Recommendation: quarterly for full
   screen, monthly for watchlist maintenance.

4. **Screening thresholds:** MVP uses tightened thresholds (CAGR >=15%,
   ROIC >=20%). Should these be configurable via a brain file or
   hardcoded in the Python script? Recommendation: brain file
   (`investing/config/screening-thresholds.json`) for easy adjustment
   per market cycle without code changes.

5. **EU data timing:** When does Suggi want to target EU companies? US
   pilot first validates the methodology with free, high-quality data.
   EU requires a paid API. Timeline preference?

6. **Sentiment agent scope:** Should the sentiment/news analysis (Stage
   4C) run on ALL broad screen companies or only those that pass Stage 3?
   Running earlier provides context for the triage decision but
   significantly increases token cost. Recommendation: run on PASS
   companies only (Stage 4), but include basic news check in Stage 3
   (no deep sentiment analysis).

7. **Position sizing finality:** Should position sizing be a
   recommendation (current design) or a hard gate? Recommendation:
   recommendation only. Position sizing involves portfolio context and
   tax considerations that are Suggi's domain. The pipeline provides
   the Kelly calculation; Suggi decides.

8. **Debate protocol depth:** Maximum 2 debate rounds before escalation.
   Is this sufficient, or should there be more rounds for close calls?
   AlphaAgents research used 3+ rounds, but each round adds token cost.
   Recommendation: 2 rounds, with option for Suggi to request a third
   on high-conviction disagreements.

9. **Archive policy:** When should old company analyses be archived?
   Analyses older than 12 months on non-held companies become stale.
   Recommendation: archive to `investing/archive/{TICKER}-{DATE}.md`,
   keep current analysis in `investing/companies/{TICKER}.md`.

10. **Library topic trigger:** Should every deep dive produce a library
    topic, or only those with genuinely novel industry insights?
    Recommendation: only novel insights. Writing library topics for
    every company dilutes the library. The company analysis files serve
    as the primary research artifact.
