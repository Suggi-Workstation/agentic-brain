# Library Writer Test -- Expected Results

## Purpose

This proposal defines the expected outputs when Researcher-1 runs the
`library-writer` skill after the discoverer has populated the candidate
queue. The writer must pick the highest-scored candidate, read the domain
anchor, research the topic via web search, score across 4 dimensions,
and -- if score >= 7.0 -- write a topic file following the
`governance/template-library.md` format.

This document is the acceptance criteria. Compare actual outputs against
these expectations after the test run.

## Prerequisites

- `library/candidate-queue.md` has at least one candidate with status `proposed`
- The candidate's domain has an anchor file at `library/<domain>/anchor-<domain>.md`
- `governance/template-library.md` is accessible in the cloned brain

## Expected Outputs

### 1. Topic file (if score >= 7.0)

File at `library/<domain>/<topic-slug>.md` following template-library.md format:

**Frontmatter** (7 required fields):
```yaml
---
name: <topic-slug>
id: <YYYYMMDDTHHMMSSZ>
tier: library-topic
domain: <domain-slug>
author: Researcher-1
tags: [<tag>, <tag>]
links: [<path>, <path>]
---
```

Acceptance criteria:
- name matches filename slug (lowercase kebab-case)
- id generated by `date -u +'%Y%m%dT%H%M%SZ'` (not human-rounded, not ending in 000000Z)
- domain matches the folder name exactly
- No `audited` or `audit-score` fields (added later by auditor)
- All 7 fields present

**Body structure:**
- Title: level-1 heading making a claim (not a label)
- Opening paragraph: 2-3 sentences summarizing the topic
- Body sections: `## Background`, `## Core Concepts`, `## Evidence`, `## Implications` (or logical equivalent)
- Sources: `## Sources` section with at least 3 sources, each annotated [high]/[medium]/[low]
- Cross-references: `## See Also` section with at least 1 link

**Quality gates (G1-G10 from template-library.md):**
- G1: Title makes a claim
- G2: Opening paragraph is self-contained
- G3: Every claim is sourced
- G4: Sources have authority ratings (at least 2 high/medium)
- G5: Cross-references exist
- G6: Domain anchor compliant (In scope, not Out scope)
- G7: Topic similarity checked (overlap estimate recorded)
- G8: Frontmatter complete
- G9: ASCII-only, lowercase slugs, hyphens
- G10: Written to correct path

Acceptance criteria:
- All 10 gates pass (or the topic was not written)
- ASCII-only: zero non-ASCII characters
- File written ONLY to `/tmp/brain-writer/library/<domain>/`, not to workspace

### 2. Scoring recorded

The writer scores the candidate across 4 dimensions before writing:

| Dimension | Weight | Expected range |
|:--|:--|:--|
| Core match | 0.35 | 5.0-10.0 (topic must be central to domain) |
| Scope fit | 0.35 | 5.0-10.0 (must fit In scope) |
| Knowledge value | 0.20 | 3.0-9.0 (with 0 existing topics, compounding value is hard to assess) |
| Source authority | 0.10 | 3.0-9.0 (depends on web search quality) |

Acceptance criteria:
- All 4 dimensions scored with justifications
- Weighted score >= 7.0 for the topic to be written
- If score < 7.0: logged to library.log with FLAG (5.0-6.9) or REJECT (<5.0)
- Topic similarity check completed, overlap estimate recorded

### 3. library.log entry

```
## [ENT-NNN] | YYYY-MM-DD HH:MM UTC | Researcher-1 | library | ref: library/<domain>/<topic-slug>.md | see: <candidate-id>
Wrote topic <title> to <domain>. Weighted score: X.X/10.0
(core=X.X, scope=X.X, value=X.X, authority=X.X).
Similarity overlap: X%. Sources: N (N high, N medium, N low).
Cross-references: N topics.
```

Acceptance criteria:
- ENT counter increments from last library.log entry
- All scores listed with 1 decimal place
- Source count matches the Sources section
- Candidate removed from queue after writing

### 4. Candidate queue updated

The processed candidate is removed from `library/candidate-queue.md`.

### 5. errors.log (expected: no entry)

Same as discoverer test. No error entry unless something genuinely failed.

## Edge Cases

| Scenario | Expected behavior |
|:--|:--|
| Queue is empty | Log to library.log, exit |
| Candidate score < 7.0 | Log FLAG/REJECT to library.log, do not remove from queue (status becomes rejected) |
| Candidate >= 80% overlap with existing | Log DUPLICATE, skip |
| Domain has no anchor | Log error, skip |
| Web search returns low-authority sources only | May still write if authority >= 3.0 and weighted score reaches 7.0 |
| Push conflict | Pull --rebase, resolve, push |

## Open Questions

1. With 0 existing topics, similarity overlap will always be < 50%. Is the overlap check meaningful on the first topic?
2. Will web search find high-authority sources for the proposed topics? The discoverer picks gaps -- some may be niche with only medium/low sources.
3. Will the writer's 4-dimension scoring produce a score >= 7.0? If all topics score 5.0-6.9, the queue fills with FLAG entries and nothing gets written.
4. Will the writer read from `governance/template-library.md` as instructed? The skill says "read it, follow it exactly" -- but if the writer skips this step, the output format will be wrong.
5. Should the writer process one candidate per cycle or all? The skill says "one per cycle" -- verify the cron runs exactly one.
